Connecting n8n or Node-RED

Send the token in an Authorization header on every request. In n8n use an HTTP Request node with Header Auth; in Node-RED set the header on the http request node. 

Authorization: Bearer YOUR_TOKEN

Watch for new posts

For syndicating to social media, poll the feed. It needs no token, returns JSON, and lists the twenty most recent published posts. Drafts and scheduled posts never appear in it. 

GET {{.BaseURL}}/feed.json

Publish a post

curl -X POST {{.BaseURL}}/api/posts \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Posted from a script",
    "body": "Written in **markdown**.",
    "tags": ["automation"],
    "draft": false
  }'

Upload an image

The response carries the stored path. Put that into a post body as ![description](path) and it renders as a figure with a lightbox. 

curl -X POST {{.BaseURL}}/api/media \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@photo.jpg"

MethodPathWhat it doesToken

GET/api/settingsEverything on this Site Settings tabYes
PATCH/api/settingsChange some of itYes

A settings change is a partial update: send the fields you want to change and the rest keep their values. Your username, your password, and these tokens are not reachable over the API at all, only from a signed-in browser session, because a token that could change the password it was issued under could not meaningfully be revoked.

Listing is cursor paginated rather than by page number. Pass the next value from a response back as ?before= to get the following page. A cursor cannot skip or repeat a post when something is published midway through, which page numbers can.

PATCH is a genuine partial update: any field you leave out keeps its current value, so flipping a draft to published is a one-field request.
